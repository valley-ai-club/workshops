Before you start

Open this downloaded handout in your browser and sign in to GitHub in another tab. The fields below personalize the starter text on this page. Use your first name or a nickname. Keep your school, schedule and personal contact details private. If you are under 13 or can’t sign in, design locally and pair with a mentor for the GitHub demonstration.

Tutorial 1 · Build your GitHub profile

Make the commit we missed last time

  1. On GitHub choose + → New repository. Name it my-first-repo, choose Public, turn on Add README, and create it. If you already have it, edit its README.
  2. Open README.md and choose the pencil. Open last time’s About Me template in a new tab and use Raw to copy the Markdown, or use the short starter below. Fill in the answers in your own words and remove optional details.
  3. Choose Preview. Check the heading, list and link. Choose Commit changes, enter Add my About Me introduction, and confirm. Back on the file list, open Commits, then your commit. Show a partner one line you added.

Get the first version online


    

  1. First Pages site? Create the public repository YOUR-USERNAME.github.io and turn on Add README so the branch exists. Use lowercase for the website repository name. Download index.html above. Use Add file → Upload files, select that single file, and commit it to main. It belongs at the top level of the repository.
    2. 

  2. Already have a site from November 6? Keep your current homepage. Use Add file → Create new file to add portfolio.html on the same branch and paste in the starter source. Add a link to it in your existing index.html, for example <a href="portfolio.html">My portfolio</a>. Your new design will live at /portfolio.html.
    3. 

  3. Inside the site repository, go to Settings → Pages → Build and deployment. For a new site, select Deploy from a branch → main → / (root) → Save. If your existing site already deploys successfully, keep its settings and use its publishing folder. Open Actions to follow the deployment.
    4. 



Change what visitors see


    

  1. On GitHub, open your HTML file and click the pencil. Find EDIT 3. Write a one-sentence introduction only you would write. Under EDIT 4, give your project a question, your approach, and a result in plain English. Check the result against the artifact before publishing.
    2. 

  2. Near EDIT 2, change --accent from #164e43 to #49213e and --highlight from #cfed9d to #f2cbea, or choose your own readable pair. These values control multiple places on the page. In EDIT 5, write what you learned and what you would try next.
    3. 

  3. Commit with a message that says what changed. Under Settings → Pages → Visit site, open your site (or its /portfolio.html page). Publishing can take up to ten minutes. While it builds, reopen your profile README and add [My portfolio](YOUR-LIVE-URL). Paste the same live URL into Edit profile → Website.
    4. 



Checkpoint. From the live site, click the project evidence and GitHub links. Narrow the window until the two columns stack. Press Tab, then Enter to open a link or expand the project detail.







The 30-second visitor test


Swap links. Imagine you are choosing a teammate for the next club project. Start on their GitHub profile. Within 30 seconds, open their site, find a specific technical skill, and point to the file or demo that shows it. Tell them one sentence they should keep and one thing you had to hunt for. Switch roles. Fix one issue and commit.


If something looks wrong

SymptomFirst check


No profile READMEThe profile repo is public, matches the username and has a nonempty README.md in its root.


A profile gadget looks brokenThe banner file and profile README must be side by side with matching filenames. For a badge, check the username and public repository. Use the history link while the image refreshes.


Website gives a 404Use the URL in Settings → Pages. Check the publishing branch, folder and lowercase filename. Check the latest Pages run in Actions. For an existing site, include /portfolio.html.


The old design appearsConfirm the commit is on the published branch. Wait for deployment to finish and hard-refresh (Ctrl/Cmd + Shift + R).


The evidence link failsOpen the public artifact on GitHub, copy its real address, and correct the link on both pages. Test in a signed-out window.
